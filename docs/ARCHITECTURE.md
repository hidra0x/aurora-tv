# Как работает Aurora TV

## 1. Это лончер, а не прошивка

Aurora TV — обычное Android-приложение с `HOME`-интентом. Android запускает его
при загрузке ТВ и по кнопке Home. Штатная система, драйверы, декодеры и тюнер
остаются на месте, поэтому:

- нет риска «кирпича»;
- откат — удаление APK;
- обновления ставятся как обычное приложение.

`MainActivity` имеет фильтры `HOME` и `LEANBACK_LAUNCHER`. После установки
скрипт выполняет:

```text
cmd package set-home-activity --user 0 ru.auroratv.launcher/.MainActivity
```

На Android 7 без `--user 0` команда на этой прошивке не применялась — это
проверено на устройстве.

## 2. Главный экран и пульт

- UI построен на обычных `View`/`RecyclerView`, без Compose и тяжёлых SDK.
- Фокусом управляет Android TV framework: каждая плитка — `focusable` View
  с drawable-селектором и короткой анимацией масштаба.
- Удержание `OK` на плитке вызывает `OnLongClickListener` и добавляет/убирает
  приложение из избранного.
- Избранное хранится в `SharedPreferences` как список package name.
- `Menu` открывает настройки, `Back` возвращает на главный экран.
- После перезагрузки `MainActivity` поднимается как домашний экран; Home из
  приложений возвращает в Aurora.

## 3. Список приложений и иконки

- `PackageManager.queryIntentActivities` ищет `MAIN` + `LEANBACK_LAUNCHER` и
  `MAIN` + `LAUNCHER`.
- Дубликаты по package name схлопываются, приоритет — leanback-активности.
- Иконки и баннеры рендерятся в фоне в `Bitmap` нужного размера и кэшируются
  в `LruCache` (24 МБ). UI не блокируется.
- Системные приложения скрыты по умолчанию; переключатель есть в настройках.
- Технические записи вроде daemon/plugin не попадают в список кнопки ТВ.

## 4. Погода

- Город по умолчанию выбирается по системной таймзоне (например,
  `Asia/Yekaterinburg` → Екатеринбург).
- Провайдеры: MET Norway (`api.met.no`), фолбэк — Open-Meteo.
- Запрос содержит только координаты города; нет ID устройства, аккаунта и
  рекламных идентификаторов.
- На Android 7.0 системный trust store не содержит нужные корневые CA, поэтому
  в APK включены официальные `ISRG Root X1` и `HARICA TLS RSA Root CA 2021`
  через `network_security_config.xml`. Проверка TLS не отключается.
- Кэш — 30 минут; погоду можно выключить, тогда сеть не используется.

## 5. Медиа

- На Android 7–9: прямой проход по `Movies`, `Music`, `Download`, `DCIM` и
  USB-томам `/storage/*` (нужно `READ_EXTERNAL_STORAGE`, `install.ps1` выдаёт
  разрешение автоматически).
- На новых Android: SAF (`ACTION_OPEN_DOCUMENT_TREE`), доступ только к
  выбранной папке.
- Плеер — Media3/ExoPlayer, поддерживает видео/аудио и очередь файлов.
- Воспроизведение проверено на тестовом MP4 на реальном ТВ.

## 6. Приватность

- Нет Firebase, аналитики, рекламных SDK и Google Play Services.
- Нет `QUERY_ALL_PACKAGES`: видимость приложений ограничена `<queries>`.
- Единственные сетевые запросы — погода (MET Norway/Open-Meteo).
- Медиатека не отправляет список файлов наружу.

## 7. Сборка

- Kotlin, AGP 8.5.2, Gradle 8.7, JDK 17, compileSdk 34, minSdk 23.
- Release подписывается локальным keystore (`keystore.properties`, в git не
  попадает), R8 + shrinkResources.
- Debug/release собираются скриптами `scripts/build.ps1`.
- GitHub Actions собирает debug APK без секретов.

## 8. Почему v2 будет своим прокси, а не VPN

Проверено на устройстве:

- VPN-приложения не могут получить согласие: пакет
  `com.android.vpndialogs` в прошивке отсутствует;
- ByeByeDPI в режиме **Proxy** поднимает локальный SOCKS5 на
  `127.0.0.1:1080` без VPN;
- SmartTube имеет встроенную настройку SOCKS-прокси
  (`Общие → Интернет-цензура`);
- текущая стратегия ByeByeDPI пропускает `curl` через SOCKS, но TLS-хендшейк
  YouTube внутри SmartTube иногда уходит в таймаут.

Поэтому v2 добавляет **свой локальный SOCKS5-прокси с TLS-фрагментацией**:
это не VPN, не требует `VpnDialogs` и позволяет управлять стратегией обхода
из Aurora TV. Подробности — в `ROADMAP.md` и `docs/SMARTTUBE.md`.
